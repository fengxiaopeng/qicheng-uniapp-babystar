# 宝宝积分：单机版开发指南

## 产品与管理入口

底部为首页、任务、奖励、我的。管理员在「我的 → 家长管理」通过紧凑列表进入任务与奖励设置；宝宝档案保留在个人资料区。首页只保留一个孩子切换入口，家庭成员管理集中在「我的」。任务设置管理当前宝宝的常驻计划；奖励设置分别管理心愿、幸运转盘与上传图片刮卡；转盘页面也提供直达奖项设置的入口。记录成员可以完成任务、兑换奖励和查看历史，不能修改任务或奖励规则。

| 模块 | 入口文件 | 职责 |
| --- | --- | --- |
| 首页 | `src/pages/index/index.vue` | 余额、今日任务、心愿、统计与宝宝切换 |
| 任务 | `src/pages/tasks/index.vue`、`edit.vue` | 今日/全部、分类、执行周期和记分 |
| 家长管理 | `src/pages/manage/tasks.vue`、`rewards.vue` | 任务计划及两种奖励设置 |
| 奖励 | `src/pages/rewards/index.vue` | 心愿兑换、转盘、图片刮卡 |
| 兑换记录 | `src/pages/rewards/history.vue` | 已完成的兑换流水，无领取状态和后续确认 |
| 成长记录 | `src/pages/records/index.vue` | 周/月统计、收支、记录人筛选和任务冲正 |
| 家庭与宝宝 | `src/pages/family/index.vue`、`children/index.vue` | 本机角色与独立宝宝档案 |

任务提醒只保存时间偏好，不发送消息。家人添加和角色切换发生在本机，并非真实邀请或认证。首次演示数据包含「朵朵」的任务、128积分以及一份图片刮卡，其他宝宝从空白档案开始。

## 分层与入口

```text
pages / components                  页面、表单、动画和用户反馈
application/use-baby.ts             响应状态、请求锁、日历刷新、数据源装配
BabyRepository                      异步 load / execute 契约
  data/local-repository.ts          本地校验、串行事务与持久化
  data/migrate.ts                   旧版快照迁移
  data/local-image.ts               平台临时图片转换为可持久化 data URI
  domain/commands.ts                纯业务命令与原子事务
  domain/rules.ts                   余额、周期、次数、图片来源与转盘规则
  domain/types.ts                   实体、命令、仓储和回执类型
  domain/seed.ts                    演示数据
```

领域层不依赖 Vue、`uni`、Canvas 或网络。页面不直接修改账本或本地存储；业务写操作通过统一命令检查、保存并返回回执。只有持久化成功后才替换展示快照。命令 ID 用于幂等，按钮禁用只是交互辅助。

三种奖励的组件分别在 `src/features/baby/components/rewards/` 中。`ScratchTile.vue` 只负责擦除遮罩和手势反馈，不负责扣积分。主题与控件在 `src/style/baby.scss`，奖励视觉在 `src/style/rewards.scss`。插画使用项目本地 SVG。

## 任务执行规则

任务设置一次后长期保留，按本机日历日期安排，无需每天新建任务：

- **每天**：每天执行，单日次数在次日自动重新计算。
- **单次**：从指定日期起执行一次，过期未完成会继续保留；完成当天仍显示反馈，之后不再进入今日列表。撤销后重新可执行，跨日也不能重复完成。
- **周末**：每周六、周日自动出现，两天分别计算单日上限。
- **指定星期**：在所选星期自动重复。兼容旧版 `weekly` / `custom` 数据。

应用在进入页面时刷新日历，并在跨零点时更新计算状态，不复制或重新生成任务。分类统一由 `TASK_CATEGORIES` 定义：学习成长、生活习惯、运动健康、兴趣爱好。

记分保存当时的任务名称、分值、操作人及时间；编辑任务不重写历史。撤销通过关联冲正记录返还执行次数，不删除原始条目，且余额不足时不能撤销已消费的积分。停用任务仅影响未来执行。

## 奖励兑换即完成

普通心愿确认后，在同一事务中扣分并生成完成流水；转盘中奖即生成完成流水。没有待领取、发放、取消或新的兑换退款流程。记录页面只展示已经完成的兑换，`RewardOrder` 不包含 `status`。

转盘结果先保存，再播放动画；费用和次数在命令内检查。中奖与未中奖均扣10积分，每天最多3次。退出不会丢失结果，完整概率在界面公示。

### 可配置转盘

`WheelSettingsEditor.vue` 负责表单，`saveWheel` 负责权限及业务校验。每位宝宝分别保存2–8个奖项，可设置名称、图标和是否为奖励（鼓励项不产生兑换）。

- 默认 `equal` 模式：所有奖项的权重为1，机会均为1/N。增删后自动平分，不需要人工填写百分比。
- `custom` 模式：百分比最多两位小数，在边界转换成整数基点，100%对应10000。保存必须合计10000，允许0概率奖项，拒绝负数、科学计数法和超精度输入。
- 转盘格子等大展示；完整概率列表明确显示实际概率，等概率百分比为近似值。抽奖使用实际权重，不根据格子面积决定结果。
- 回执保存本次 `wheelPrizes` 快照与结果索引；动画消费这份快照，之后编辑奖项不改写历史名称或抽奖结果。切换宝宝会停止当前动画，已保存结果仍归属原宝宝。
- 保存设置不会扣分或恢复当日次数。

快照中的 `wheelSettings` 为可选字段。已有v2数据缺少该字段时，按等概率默认设置读取，不重置账本，不重新初始化用户数据；保存时才写入当前宝宝的配置。已有配置格式不合法时保留原始数据并提示错误。

## 上传图片刮卡

1. 管理员上传图片并设置奖励名称、4/9/16格、每格积分。
2. 图片在本地转换为 data URI，持久化原图一份。格子由同一张底图和覆盖网格组成，不复制多份裁剪图，也不保留会失效的 blob 或临时文件路径。
3. 点击未支付的格子先确认消耗；`buyScratchPiece` 原子扣分并关联账本。即使使用另一个命令 ID 重复购买同一格，也不会重复扣分。
4. 支付后滑动擦除 Canvas 遮罩，达到覆盖阈值后 `revealScratchPiece` 保存该格已揭开。也提供「直接揭开」入口，便于鼠标或无障碍操作。仅当前选中的已支付格子使用画布，其余已支付格子可免费继续。
5. 刷新保留已支付及整格揭开进度。未完成的局部笔划不持久化，但再次刮开不收费。
6. 全部格子揭开后调用 `redeemScratch` 完成兑换，不再额外扣分。账本保留每格消耗，最终兑换条目为0分；兑换流水记录实际累计费用和图片快照。已完成的活动不能再次兑换。
7. 第一次支付之后锁定图片、格数和价格，避免已消费的进度被重置；需要其他规则时新建活动。

H5 将图片缩至最长边1000px并压缩为JPEG；微信端压缩后使用文件系统读取为base64。超出约1MB限制时提示重新选择。写入空间不足则整笔失败，保留现有积分和进度。相册、摄像头权限以及微信画布操作需要在实际设备上验证。

## 存储升级与备份

快照版本为 `version: 2`，继续使用历史键 `babystar:family:v1`，以便安全读取已有用户数据。不能按键名推断快照版本。

`migrate.ts` 将 v1 快照迁移为 v2，并在完整校验后才写回：

- 保留任务、宝宝、成员、积分账本和回执，不重新生成演示数据。
- 历史已领取或待领取兑换，按新规则进入完成流水，不再次扣分。
- 历史已取消兑换及旧任务卡片保存在 `legacy` 中，导出备份仍然包含，不会将已取消记录误计为已完成奖励。
- 原始退款和冲正账本保持不变，所以迁移前后余额一致。
- 图片刮卡从空列表开始，不将旧卡片或积分自动兑换成新格子。

只有确实没有数据时才初始化演示数据。未知版本或校验失败停止加载，不覆盖原始内容。设置支持导出全部家庭数据：H5下载JSON，微信复制到剪贴板；暂不提供自动恢复或跨设备同步。当前事务队列保证单个应用实例内顺序，多标签页及跨设备并发需要服务端处理。

## 后续 API 接入

在 `src/api/baby/` 中按项目 HTTP 规范实现请求和响应校验，再实现 `BabyRepository` 并替换 `use-baby.ts` 的唯一装配点。页面不能自行调用 `uni.request`。

真实身份与权限、家庭/宝宝归属、余额、单次任务终身完成次数、周期时区、逐格扣款、转盘随机结果、幂等及兑换防重都由服务端检查，不能信任本机角色。请求需明确家庭/宝宝 ID，操作人由登录身份确定。

图片上传适配器未来应先上传文件并取得稳定资源 ID，再创建活动；不要在页面散落上传逻辑。服务器保存每格支付关联与完成时间，支持超时后查询结果，避免重试重复扣分。旧本地演示数据迁移到真实账号需要用户明确确认，不能自动导入为线上账本。

## 验证

使用 Node 24 和 pnpm 10.10.0：

```bash
pnpm test:run
pnpm type-check
pnpm lint
SKIP_OPEN_DEVTOOLS=true pnpm build:mp
pnpm build:h5
```

切换构建平台前停止自己启动的开发进程，避免并行写入 `src/pages.json` 等生成物。不要手工修改生成配置。

领域测试覆盖每日跨日、单次、周末、兴趣分类、幂等和上限、立即完成兑换、转盘等概率/自定义概率及结果快照、刮卡重复付款/未付款揭开/集齐兑换、权限、多宝宝隔离、版本迁移、存储失败。浏览器验证应覆盖家长入口、真实上传与图片持久化、滑动擦除、刷新恢复、全部揭开兑换、无领取状态及跨零点刷新。
