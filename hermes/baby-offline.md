# 宝宝积分：单机版开发指南

## 范围与入口

当前产品在现有 uni-app / Vue 3 工程中实现，无需登录或后端服务。底部入口为首页、任务、奖励、我的。H5 和微信小程序使用同一套组件、规则和数据接口；路由仍由 `definePage` 和 `pages.config.ts` 生成。

| 页面 | 文件 | 职责 |
| --- | --- | --- |
| 首页 | `src/pages/index/index.vue` | 宝宝切换、余额、今日任务、连续天数、目标进度 |
| 任务 | `src/pages/tasks/index.vue`、`edit.vue` | 分类、今日/全部、创建编辑、停用与记分 |
| 奖励 | `src/pages/rewards/index.vue` | 心愿管理、兑换确认、转盘、集卡 |
| 兑换记录 | `src/pages/rewards/history.vue` | 待领取、发放、取消及退款 |
| 成长记录 | `src/pages/records/index.vue` | 周/月统计、日期/收支/记录人筛选、明细及撤销 |
| 家庭 | `src/pages/family/index.vue` | 本机成员、权限与当前记录人切换 |
| 宝宝档案 | `src/pages/children/index.vue` | 新增、编辑、切换独立档案 |
| 我的 | `src/pages/me/me.vue` | 成长摘要、家庭入口、设置和数据导出 |

任务提醒仅保存时间偏好，暂不发送通知。家庭添加/切换发生在此设备中，并非真实邀请或登录认证。新宝宝从空白档案开始，演示宝宝「朵朵」带有可操作的示例数据。首批六张森林卡片、转盘奖项和概率属于单机版的产品默认配置，集中在领域规则及奖励页映射中；奖品规则编辑和真实家庭邀请留待联网版接入。

## 分层与依赖方向

```text
pages / components        展示、表单、导航与用户反馈
         ↓
application/use-baby.ts   响应状态、请求锁、操作结果；数据源装配入口
         ↓
BabyRepository           异步 load / execute 契约
         ↓
data/local-repository.ts 本机存储边界、结构校验、串行事务与持久化
         ↓
domain/commands.ts       纯业务命令：校验 → 新快照 → 回执
domain/rules.ts          余额、次数、日期、卡片与转盘规则
domain/types.ts          实体、命令、回执和仓储契约
domain/seed.ts           首次启动的演示数据，与页面代码分开
```

领域层不依赖 Vue、Pinia、`uni` 或网络。所有写操作均经过同一命令入口，页面不直接操作存储，也不单独累加余额。`useBaby` 只在成功持久化后替换展示快照；失败保留当前页面状态并显示原因。重复操作通过命令 ID 识别，不能靠按钮置灰代替业务校验。

公共组件位于 `src/features/baby/components/`，三种奖励玩法在其中的 `rewards/` 下分别维护，根页面仅负责余额与标签导航。主题变量与基础控件样式位于 `src/style/baby.scss`，奖励视觉样式位于 `src/style/rewards.scss`；页面排版优先 UnoCSS。插画为项目内原创 SVG，位于 `src/static/baby/`，不依赖外部图片/CDN。新增图标需同步 UnoCSS safelist。修改设计颜色、圆角和按钮时先调整公共层，避免每页重复修改。

## 账本和业务约束

- 余额由当前宝宝的账本求和得到，不另存一个容易失配的余额字段。积分是整数，不支持负余额。
- 每次任务记分保存当时的任务名、积分、记录人姓名和时间，同时发放对应图标的卡片。修改任务或成员名称不回写历史。
- 任务按本机日历日期计算单日上限。每天重复不限制星期；每周/自定义使用选定的星期。停用只影响后续执行。
- 撤销任务记分会生成关联冲正条目，收回对应卡片并恢复记录次数，不删除原始记录。余额不足、非本人且非管理员、卡片已经用于兑换时拒绝撤销。
- 普通兑换原子性扣分并生成待领取订单；管理员发放后进入已领取状态。只能取消待领取订单，普通兑换取消退积分，且只能退款一次。
- 转盘先在命令内决定并保存结果，再播放视觉动画。退出或刷新不会丢失结果。每次10积分，每日最多3次；全部概率（含未中奖）在规则面板公示。取消转盘奖品不退参与费用，也不恢复次数。
- 集卡要求六种不同卡片各一张，兑换只消耗卡片、不扣积分，允许后续继续收集。取消待领取的集卡订单退回原卡片。
- 管理员管理任务、奖励、宝宝、家庭、发放/取消奖励并纠正记录；记录成员可记分、兑换与撤销自己记下的任务积分。至少保留一位管理员。单机角色切换只用于体验，不能作为联网版的安全边界。
- 统计的「获得积分」仅包括未撤销的任务收入，不包含初始赠送；「完成任务」按未撤销条数计算。消费统计扣除普通兑换退款。每位宝宝的积分、任务、奖励、卡片和订单相互独立，成员属于共享家庭。

## 存储、备份与边界

本机存储键为 `babystar:family:v1`。快照带 `version: 1`。仅首次没有数据时初始化演示数据；未知版本或校验失败会停止加载并保留原始数据，不静默覆盖。存储空间不足时整笔写入失败，不先更新界面余额。

设置中可以导出所有宝宝及家人的 JSON 快照：H5 下载文件，小程序复制到剪贴板。当前不提供导入/自动恢复；不要将备份当作已经同步到云端。清理浏览器或小程序数据、换域名、换设备都会影响本地记录。当前串行队列只保证单个应用实例内的操作顺序，多标签页同时修改和跨设备并发不在单机版保证范围内。

## 后续接入 API

1. 在 `src/api/baby/` 中按仓库 HTTP 规范添加 DTO、请求函数和响应边界校验，不在页面调用 `uni.request`。
2. 实现新的 `BabyRepository` 适配器，替换 `application/use-baby.ts` 中唯一的数据源装配点。初期可将 API 响应归一成当前快照与回执；数据量增加后再拆分页查询，保持领域类型与组件职责清楚。
3. 登录身份、家庭成员权限、宝宝归属、余额、任务次数与概率都由服务端重新校验；请求应明确携带家庭/宝宝 ID，操作人由真实身份确定，不能信任本机切换的角色。
4. 命令 `id` 映射为服务端幂等键。记分、卡片、扣分、订单及退款必须在同一服务端事务中提交，并由服务端返回最终余额与结果。转盘结果只能由服务端决定，动画继续消费回执中的结果索引。
5. 日期归属与每日上限应统一家庭时区；以服务端时间为准。约定订单生命周期、撤销与退款错误码，并处理超时后查询结果、重复提交及多人竞争。
6. 不将演示快照自动上传为真实账本；先设计用户确认的数据迁移。存储版本升级需要迁移函数与测试。将消息通知、家庭邀请及奖品规则编辑接入各自服务，不将当前本地演示包装成真实同步。

后端尚未约定时保留接口边界，不预设不存在的地址、认证参数或成功响应。

## 验证与开发

使用项目固定 pnpm 10.10.0、Node >=20（当前验证24）。

```bash
pnpm install --frozen-lockfile --ignore-scripts --registry=https://registry.npmjs.org
pnpm init-baseFiles
SKIP_OPEN_DEVTOOLS=true pnpm build:mp
pnpm type-check
pnpm lint
pnpm test:run
SKIP_OPEN_DEVTOOLS=true pnpm build:h5
pnpm dev
```

切换构建平台前先停止自己启动的开发服务，避免两个插件进程同时写 `src/pages.json` 等生成物。不要手工修改生成文件；若调试遗留了损坏的生成配置，先备份到 checkout 外，再运行 `pnpm init-baseFiles` 和目标构建重新生成。

`src/features/baby/domain/commands.test.ts` 覆盖记分幂等、每日上限、冲正、历史快照、日期规则、积分不足、退款、奖励领取、转盘概率与限制、集卡消费/退卡、权限、多宝宝隔离、并发写入、版本校验和存储失败。导航权限测试使用固定配置，独立于产品四个公开 tab。

手工回归：记分→撤销→再次记分→刷新；创建/编辑/停用任务；积分不足与正常兑换→领取/取消；转盘→退出→兑换记录；集卡缺卡/集齐/取消；周月与成员筛选；切换宝宝及记录人；窄屏、安全区与 Pages 子路径资源。
